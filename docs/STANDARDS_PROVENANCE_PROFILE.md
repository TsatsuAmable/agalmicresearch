# Agalmic Research Standards-First Provenance Profile

Version: 0.1  
Status: exploratory application profile  
Date: 7 September 2026

## Purpose

Agalmic Research previously developed a local discovery-graph and Memory Palace vocabulary before adequately checking mature provenance and contributorship standards. This profile corrects that direction.

The design rule is:

> **Use established provenance vocabulary wherever it fits. Extend only where the research problem genuinely requires information the standards do not represent.**

The Agalmic Research provenance system should therefore be treated as an application profile over existing standards, not as a new provenance standard.

## Standards stack

### 1. W3C PROV

Use the W3C PROV family as the conceptual authority for general provenance.

Canonical reference: [PROV-DM: The PROV Data Model](https://www.w3.org/TR/prov-dm/).

Primary mappings:

| Research concept | W3C PROV representation |
| --- | --- |
| paper, draft, claim object, dataset, prompt export, code artefact | `prov:Entity` |
| research session, literature search, experiment, drafting activity, review, publication event | `prov:Activity` |
| human contributor | `prov:Person` / `prov:Agent` |
| AI or software system participating in an activity | `prov:SoftwareAgent` |
| organization | `prov:Organization` |
| object generated by an activity | `prov:wasGeneratedBy` |
| object derived from another object | `prov:wasDerivedFrom` |
| source/object used by an activity | `prov:used` |
| activity associated with a contributor | `prov:wasAssociatedWith` |
| entity attribution | `prov:wasAttributedTo` |
| one object/activity influenced by another | `prov:wasInfluencedBy` |
| material contributor role | `prov:qualifiedAssociation` + `prov:hadRole` |
| provenance bundle | `prov:Bundle` |

Use qualified relations when the role, timing, evidence pointer or other qualification matters.

### 2. CRediT

Use the ANSI/NISO Contributor Role Taxonomy (CRediT) for standardized scholarly contribution roles.

Canonical references:

- [CRediT resource hub](https://credit.niso.org/)
- [ANSI/NISO Z39.104-2022](https://www.niso.org/publications/z39104-2022-credit)

The 14 standard roles are:

- Conceptualization
- Data curation
- Formal analysis
- Funding acquisition
- Investigation
- Methodology
- Project administration
- Resources
- Software
- Supervision
- Validation
- Visualization
- Writing – original draft
- Writing – review & editing

Agalmic Research should not invent synonyms for these roles.

Where the Memory Palace needs a finer distinction, record both the closest CRediT role and a local secondary role. Examples:

| Fine-grained local role | Preferred CRediT anchor |
| --- | --- |
| initiator | Conceptualization |
| framer | Conceptualization / Methodology |
| search director | Methodology / Investigation |
| generator | depends on output: Conceptualization, Formal analysis, Software, Writing – original draft |
| selector | no exact CRediT equivalent; preserve as local secondary role |
| developer | Methodology / Formal analysis / Software / Conceptualization as appropriate |
| terminology | Writing – original draft or Conceptualization; preserve local role if materially important |
| synthesizer | Conceptualization / Formal analysis / Writing – original draft |
| critic | Validation / Writing – review & editing |
| verifier | Validation |
| domain steward | Validation / Supervision |
| editor | Writing – review & editing |
| decision maker | Project administration; preserve local role when the publication/selection decision itself matters |
| realizer | Software / Investigation / Resources or other domain-specific CRediT role |

The local role is descriptive metadata. It must not be mistaken for a proposed competing taxonomy.

### 3. RO-Crate

Use RO-Crate for packaging a versioned research object with machine-readable metadata.

Canonical reference: [RO-Crate 1.3](https://www.researchobject.org/ro-crate/specification/1.3/).

A provenance-complete Agalmic Research release should be capable of becoming an RO-Crate containing or referencing:

- canonical paper/draft text;
- session packet(s) that materially contributed;
- source/evidence register;
- machine-readable W3C PROV graph;
- research data/code/models where releasable;
- prompts and visible transcript exports where releasable;
- contributor/context entities;
- software/model information where available;
- license, version, date, persistent identifier and repository commit;
- local extension metadata for epistemic status and search-space information.

The root repository now includes an experimental `ro-crate-metadata.json` to begin using this format rather than merely discussing it.

### 4. Existing graph-based scholarly communication

The Memory Palace should acknowledge and interoperate conceptually with systems such as [MIRA](https://www.mira.science/), which represents research as granular questions, claims and evidence with attribution.

Agalmic Research does **not** claim novelty for representing research as a graph of claims/questions/evidence.

Its narrower experimental addition is the preservation of:

- epistemic-authority state;
- explicit search-space branches;
- rejected/deferred/surfaced-but-unexamined alternatives;
- reversal conditions for consequential decisions;
- search-boundary statements;
- explicit epistemic handoffs;
- distinction between contribution provenance and authority over specific claims.

### 5. Decision provenance

Contemporaneous preservation of decision context is already a recognized provenance concern. Agalmic Research should use that prior art rather than presenting decision replay as a wholly new idea.

Reference: [decisionprovenance.org](https://decisionprovenance.org/).

The Memory Palace should preserve the state of evidence, available alternatives, decision, rationale and reversal condition at the time of the decision. Later reconstruction must be labelled retrospective.

## Agalmic extension namespace

Until a more appropriate established vocabulary is found, local extension terms may use:

`https://agalmicresearch.org/ns/`

Local terms should be sparse. Current candidates:

- `ar:epistemicStatus`
- `ar:authorityBasis`
- `ar:authorityHolder`
- `ar:handoffNeeded`
- `ar:branchState`
- `ar:searchBoundary`
- `ar:reversalCondition`
- `ar:attributionConfidence`
- `ar:attributionMode`
- `ar:surfacedUnexplored`
- `ar:excludedByScope`

Before adding a term, search W3C PROV, Schema.org, RO-Crate profiles, CRediT and relevant domain ontologies. A local term should exist only because an existing term is materially inadequate, not because the local wording is preferred.

## Epistemic authority is not provenance

W3C PROV can record who or what generated, influenced, used or was associated with an artefact. It does not by itself establish that an actor has epistemic authority over a claim.

CRediT can record scholarly contribution roles. It does not certify comprehension, correctness or authority.

RO-Crate can package contextual and provenance metadata. It does not turn those records into evidence that a claim is true.

Therefore the authority layer remains a local research hypothesis and should be clearly separated from standard provenance fields.

Example:

- W3C PROV: a human and a software agent participated in the activity that generated Paper 001.
- CRediT: the human performed Conceptualization and Project administration; the system materially contributed to conceptualization-like work and drafting, recorded transparently without implying formal authorship.
- Agalmic extension: the paper is `exploratory`; no domain expert presently holds authority over all claims; specified claims require handoff/review.

## AI systems in the provenance model

W3C PROV explicitly supports software agents. Record a materially participating AI system as `prov:SoftwareAgent` when model/version information is available.

Do not infer from `prov:Agent` that the system is a moral person, legal author, epistemic knower or scientific discoverer. PROV's term "agent" is a provenance role, not a philosophical conclusion about agency.

This distinction becomes especially important for the emerging **Discovery Attribution Problem**: a machine may generate a candidate while a human directs the search, recognizes significance, validates, integrates or realizes it. Provenance should record those events without prematurely collapsing them into a single word such as "discoverer".

## Recommended per-session outputs

A provenance-complete research session should aim to emit:

1. visible human-readable session summary;
2. W3C PROV-compatible JSON-LD for actors, activities, entities and derivations;
3. CRediT mappings for material scholarly contribution roles;
4. Agalmic extension metadata for authority, branch state, handoff, reversal and search boundary;
5. RO-Crate-compatible metadata for the resulting research-object package;
6. raw transcript/export references where permitted;
7. hashes, commit identifiers and persistent IDs where available;
8. a clear statement of missing evidence and unsearched domains.

## Migration policy

The existing `src/data/researchGraph.json` is an experimental local graph and should not be discarded. It records useful intellectual history. Future iterations should progressively map its ordinary provenance relations into W3C PROV and treat remaining local fields as an extension layer.

Do not silently rewrite old records to look as if the standards-first design existed from the beginning. Record the migration as a new provenance activity.

## Status

This profile itself is exploratory. A standards expert or experienced RO-Crate/W3C PROV implementer should review it before Agalmic Research claims conformance beyond the basic structures implemented in the repository.
